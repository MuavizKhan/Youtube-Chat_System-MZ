# Browser-assisted YouTube caption ingestion

## Why this path exists

The backend's direct youtube-transcript-api requests can be blocked by YouTube at the backend's public IP. Retrying the same server request for every video does not fix an IP-level restriction.

The extension acquires captions in the active YouTube browser tab and submits bounded, timestamped segments to POST /index/browser-transcript. It first inspects the current player response and prefers English, Hindi, Urdu, and Arabic before other available languages. For ordinary timed-text tracks it can fetch JSON3/XML captions directly from the page.

Some newer caption URLs include exp=xpe. YouTube can return HTTP 200 with an empty body for those URLs because it expects a proof-of-origin token generated by its own player JavaScript; this is distinct from a backend IP block. When direct timed-text retrieval is unavailable, the extension uses YouTube's own Show transcript control and reads the timestamped transcript segments rendered in the active transcript panel. It supports both the modern transcript-segment-view-model elements and the legacy ytd-transcript-segment-renderer elements, waits for the segment list to stabilize, and verifies that the rendered video still matches the URL. See the upstream [youtube-transcript-api PO-token issue](https://github.com/jdepoix/youtube-transcript-api/issues/592) for the gated timed-text behavior.

The backend validates and stages the transcript, then dispatches the existing durable index worker. The worker consumes the staged transcript through the same get_transcript -> documents -> timestamped chunks -> embeddings -> FAISS flow. Retrieval and answer generation are unchanged.

## Fallback behavior

If browser acquisition still fails (for example, there is no usable transcript panel or captions are not available), the extension retains the existing POST /index path as a last fallback. The specific browser-stage failure is carried through the queued job and shown alongside the backend result instead of being lost when the UI switches to status polling. Browser status polling uses exponential backoff and prevents overlapping requests so a failed preparation does not exceed the status endpoint's rate limit. The backend youtube-transcript-api remains a fallback. IpBlocked and RequestBlocked become an explicit YOUTUBE_IP_BLOCKED failure instead of a generic message.

The official YouTube Data API captions.list and captions.download methods are OAuth-authorized management methods; downloading a caption track requires permission to edit the video. They do not provide arbitrary public-video transcript downloads for an ordinary API key.

## Limits

The browser-caption upload is limited to 16 MiB, 100,000 segments, and 1.5 million caption characters. The backend stages the transcript under data/browser_transcripts/, consumes it once, and that directory is ignored by Git. The normal request-body limit for chat and feedback remains unchanged.

This does not make private, unavailable, age-gated, browser-blocked, or no-caption videos transcribable. A separate audio-to-text fallback would be required for those cases. This change improves coverage for public videos whose caption tracks are available in the YouTube player, including auto-generated tracks.

## Manual verification

1. Load the updated unpacked extension after restarting the backend.
2. Open a public YouTube video with captions (including auto-generated captions).
3. Confirm browser caption ingestion creates an index and status becomes ready.
4. Ask a question and confirm timestamped sources still work.
5. Test a video without a caption track and verify the backend fallback reports the actual failure category.
6. Check data/browser_transcripts/ is empty after successful indexing.
